# DEMO: Lawn Desk

flue, flue/react, cloudflare

## 누구를 위한 에이전트이고, 어떤 업무를 대신하는지

**Dave를 위한 에이전트다.** Dave는 동네 잔디 깎기 서비스를 혼자 운영하는 가상의 1인 자영업자다. 오전 내내 잔디를 깎는데, 잔디깎이 소음 때문에 작업 중에는 전화도 문자도 받지 못해서 일이 끝난 뒤 몰아서 답한다.

**에이전트는 Dave 대신 손님 문자에 답한다.**
- 손님 문자에서 이름, 주소, 동네, 마당 크기를 뽑고, 빠진 것만 되묻는다.
- Dave의 요금 규칙대로 견적을 안내한다.
- Dave가 그 동네에 가는 요일 중 빈 시간 두 개를 제안한다.
- 손님이 고른 시간으로 예약을 잡는다.
- 스스로 정할 수 없는 문의는 Dave에게 넘긴다: 서비스 지역 밖, 1 acre 넘는 마당, 불만, 환불, 가격 흥정.

데모는 실제 SMS 대신 웹 문자 시뮬레이터로 만든다. 전화번호 없이 브라우저에서 바로 테스트할 수 있다.

## 진행 상황

feature를 merge할 때마다 갱신한다.

**지금 되는 것**
- Cloudflare Worker 두 개로 나눴다. `backend/`는 Workers AI로 Flue 에이전트를 돌리고, `frontend/`는 문자 시뮬레이터 화면(React)을 띄우고 `/api/*`를 service binding으로 backend에 넘긴다.
- 에이전트 응답은 스트리밍으로 돌아온다.
- Dave의 업무 규칙을 코드로 만들고 테스트했다(`backend/src/domain/`, 테스트 68개):
  - 근무 시간 8 AM-1 PM, 동네별 근무 요일, 시간당 $45 요금표
  - 견적: ½ acre 이하 1시간 $45, 1 acre 이하 1.5시간 $67.50, 1 acre 초과는 Dave에게 넘김(딱 1 acre는 견적), 크기를 모르면 1시간 견적 후 현장에서 조정
  - 빈 시간 찾기: 그 동네 근무 요일에 30분 단위로, 1 PM 전에 끝나고 기존 예약과 겹치지 않는 시간
  - 테스트용 예약 일정 4종(seed preset)
- 방문자별 예약 달력을 만들었다(`backend/src/store/`, 테스트 25개). 방문자마다 Durable Object 하나가 자기 달력을 갖는다.
  - 처음 열면 테스트용 예약 일정 4종 중 하나로 시작한다.
  - 예약을 추가할 때 겹치는 시간, 규칙에 어긋나는 시간, 이름 없는 예약을 거부한다. 가격은 저장소가 마당 크기로 직접 계산한다.
  - reset하면 새 generation으로 바뀌고, 지금과 다른 일정으로 다시 시작한다.
  - `GET /api/config`(Dave의 규칙), `GET /api/calendar/<visitorId>`, `POST /api/calendar/<visitorId>/reset`
- 리뷰어 로그인을 만들었다(`backend/src/auth/`, 테스트 42개).
  - 공유 access code와 닉네임으로 로그인하면 2시간짜리 서명 token을 준다(`POST /api/auth`).
  - 닉네임은 정규화(대소문자, 앞뒤 공백, 보이지 않는 문자)한 뒤 HMAC으로 바꿔 allowlist(Workers KV)와 비교한다. 닉네임 목록 원문은 repo에 넣지 않고, `scripts/allowlist.ts`로 바꾼 값만 KV에 넣는다.
  - 같은 닉네임은 어느 브라우저에서 들어와도 같은 `visitorId`와 같은 달력을 쓴다.
  - 달력과 에이전트 route는 token이 없거나 만료되면 401, 다른 방문자 것이면 403, 5분에 쓰기 30번을 넘으면 429를 준다.
- 에이전트가 Dave의 규칙과 달력으로 일한다(`backend/src/desk/`, `backend/src/agents/`). API만으로 예약부터 Dave에게 넘기기까지 된다.
  - tool 4개: `quoteJob`(견적), `findSlots`(빈 시간 2개), `bookSlot`(예약), `handoffToDave`(Dave에게 넘기기). 가격, 작업 시간, 빈 시간은 모델이 아니라 tool과 저장소가 계산한다.
  - 예약 전에 손님 이름을 묻는다. 손님이 문자로 보낸 이름과 거리 주소로만 예약한다: 서버가 손님이 보낸 문자를 기록해 두고, 거기 없는 이름이나 주소면 예약을 거부하고 에이전트에게 다시 물으라고 한다. 예약하면 손님 이름도 같이 기록한다.
  - 서비스 지역 밖, 1 acre 초과, 불만, 환불, 흥정은 사유마다 정해진 답장을 보낸다. 왜 받을 수 없는지(예: Dave가 일하는 네 동네)를 말하고, Dave가 직접 연락한다는 말로 끝난다. 동시에 Dave 폰으로 정해진 형식의 문자를 보낸다: 넘긴 사유와 손님이 보낸 최근 문자 세 개를 그대로 인용한다.
  - 예약이 되면 Dave 폰에도 누가, 언제, 어디서, 얼마인지 정해진 형식의 문자가 간다. 예약과 같은 저장 단계에서 남는다.
  - Dave 폰 문자는 모델이 쓰지 않는다. 방문자 저장소에 쌓이고 달력 응답(`daveTexts`)으로 나간다. 예전 Dave 대화(`/api/agents/dave-phone/...`)는 읽기만 된다.
  - 손님에게 계산식(`0.75 acre → 1.5 h × $45`)을 보내지 않는다. 견적과 예약 tool은 모델에게 계산 근거를 주지 않고, 프롬프트는 가격과 시간을 말로 쓰게 한다.
  - 인사나 가격·동네·시간 같은 일반 질문에는 규칙에서 바로 답하고, 견적이나 예약을 원할 때만 주소와 크기를 묻는다. 넘긴 뒤에도 질문에 계속 답한다.
  - 대화 id가 형식에 맞지 않으면 400, reset 전 대화에서 보낸 문자는 409다. 옛 대화가 새 달력에 예약을 넣지 못한다.
  - `scripts/m1.ts`: 로컬 dev server에서 실제 모델로 예약 한 건과 Dave 알림 한 건, 대화 규칙 5가지, "next Tuesday"가 실제 날짜로 예약되는지, 이름을 보내기 전에는 예약되지 않는지를 확인한다.
- 실제 날짜로 동작한다. "오늘"은 서버 시계를 Dave의 시간대(`America/New_York`)로 읽은 날짜다.
  - 빈 시간은 지금부터 60분 뒤 이후만 제안하고, 그보다 이른 시간은 예약을 거부한다. 손님이 고르는 사이 60분 안으로 들어온 시간은 에이전트가 다시 찾아 제안한다.
  - 테스트용 일정은 reset한 날 다음에 오는 일요일부터 두 주에 놓인다. 어느 요일에 reset해도 일정이 모두 앞날에 있다.
  - 오랜만에 다시 들어와도 일정이 비지 않는다. 첫 주가 지나면 다음 두 주 일정을 이어 붙이고, 이미 잡힌 예약과 겹치는 일정은 건너뛴다. 대화와 generation은 그대로다.
  - 달력 응답(`GET /api/calendar/<visitorId>`)에 `today`와 `timeZone`이 들어가고, 화면 헤더의 Today(예: `Thu, Dec 3, 2026 · New York time`)와 달력이 보여 주는 주가 이 값을 따른다.
  - 프롬프트에 오늘과 다음 14일의 요일·날짜를 넣어, "next Tuesday" 같은 말을 실제 날짜로 바꾼다. 날짜 계산의 기준은 여전히 tool이다.
  - 저장된 달력 형식이 바뀌어(schema 2), 기존 달력은 처음 열 때 한 번 새 generation으로 reset된다.
- 브라우저 문자 시뮬레이터의 손님 쪽 화면을 만들었다(`frontend/src/`, 손님 쪽과 Dave 쪽 합쳐 테스트 120개).
  - 로그인 화면: access code와 닉네임으로 로그인한다. 틀리면 어느 쪽이 틀렸는지 말하지 않는다. 닉네임만 브라우저에 남고 access code는 저장하지 않는다. token이 만료되거나 Sign out을 누르면 로그인 화면으로 돌아가고, 다시 로그인하면 같은 달력과 대화가 열린다.
  - 손님 폰: 손님이 문자를 보내면 에이전트가 답하는 동안 "typing…"이 보이고, 답장은 다 쓰인 뒤에 말풍선으로 나온다.
  - 손님 카드: New customer를 누르면 가상의 이름, 거리, 동네, 마당 크기를 뽑는다(가끔 서비스 지역 밖 동네). 첫 문자 전까지 고칠 수 있다. Dave 달력에 이미 있는 이름은 뽑지 않는다. 문자를 보낸 이전 손님은 목록에서 다시 열 수 있다. 열린 손님과 목록은 닉네임별로 브라우저에 남아, 새 탭이나 브라우저를 다시 열어도 이어진다.
  - 동네 지도: 손님 카드 안에 가상의 동네 일곱 곳과 길을 그리고, 손님 동네를 "You"로 표시한다. Dave 쪽이 열리면 동네가 Dave의 요일 색으로 바뀐다. 양쪽을 다 열어 카드가 좁아지면 지도가 정보 아래로 내려가면서 접히고(Show map으로 펼침), 추천 답장과 예약 상태가 화면에 남는다.
  - 손님 쪽은 문자로 들은 것만 보여 준다. 예약 상태는 에이전트의 문자가 날짜와 시작 시각을 말했을 때 예약됨이 되고, 주소·가격·시간 길이도 문자가 말한 것만 채운다(말하지 않은 칸은 "—"). Dave에게 넘어감도 문자에 넘기기 답장이 있을 때만이다.
  - 추천 답장(누르면 바로 전송, 모델이 아니라 고정 문구에 카드를 채움)은 에이전트의 문자가 말한 시간만 제안한다. 문자에 시간이 없으면 "The first time works"처럼 시간 없이 제안한다. 둘 다 에이전트의 답장이 폰에 뜬 뒤에 바뀐다.
  - 판단 기록(judgment log): 에이전트의 tool 호출(input, output)과 reasoning을 시간 순으로 보여 준다. 브라우저 개발자 도구처럼 화면 아래에 붙어 있고, 처음엔 접혀 있다(접힌 동안 새로 온 항목 수 표시). 펼치면 위 가장자리를 끌어 높이를 바꾼다.
  - 화면 높이에 맞춘다: 손님 쪽과 Dave 쪽이 judgment log가 남긴 높이를 쓰고, 폰과 달력이 그에 맞춰 줄어든다.
  - 손님 쪽, Dave 쪽, 둘 다 중 하나를 크게 볼 수 있고, 좁은 쪽은 흐리게 가려진다.
  - 다른 곳에서 달력을 reset한 뒤 보낸 문자는 새 대화로 다시 보내고, 화면에 그렇게 알린다.
- 문자 시뮬레이터의 Dave 쪽 화면을 만들었다(`frontend/src/DavePanel.tsx`).
  - Dave 달력(FullCalendar v7 주간 보기): 요일 아래 그날 가는 동네, 쉬는 수요일은 빗금. 미리 있던 일정은 요일 색, 에이전트가 잡은 예약은 초록색에 예약 번호(예: `g3-1`)를 붙인다.
  - 동네별 요일표와 요금표를 `/api/config`에서 만든다.
  - Dave 폰: 오른쪽 아래 버튼으로 열고(읽기 전용), 새 문자가 오면 badge가 붙는다. 문자는 달력과 함께 읽는다.
  - 예약이 보이는 순서: 에이전트의 답장이 손님 폰에 뜬 뒤 잠깐 멈췄다가, 양쪽 화면이 열리고, 새 예약이 달력에 천천히 내려앉는다. Dave 폰 문자도 이때 보인다. tool 결과가 나온 순간이 아니라 답장이 도착한 순간이 기준이다.
  - Reset all: 헤더에서 한 번 더 확인한 뒤 달력을 다른 일정으로 바꾸고 새 손님으로 시작한다.
  - 마당이 1 acre 초과라며 Dave에게 넘길 때 에이전트가 크기를 같이 넘겨야 한다. 1 acre 이하이거나 크기가 없으면 tool이 넘기기를 거부하고 견적을 내라고 한다(딱 1 acre를 넘긴 일이 있었다).
- 테스터가 자기 Google Calendar에 Dave의 두 주 일정을 복사해 볼 수 있다(`backend/src/google/`, `frontend/src/GoogleSync.tsx`, backend 테스트 20개).
  - Dave 쪽 헤더의 Sync 버튼을 누르면, 오늘부터 13일 뒤까지 어느 날짜를 복사하는지와 다른 일정은 읽지도 지우지도 않는다는 안내가 popup으로 뜬다. Agree and connect를 눌러야 Google 동의 화면으로 간다.
  - 권한은 `calendar.app.created` 하나다: 앱이 만든 캘린더와 그 일정만 다룬다. 연결하면 "Dave's Lawn Desk" 캘린더를 만들고 Dave 달력과 같은 제목(`이름 · 동네`)과 내용으로 일정을 넣는다.
  - 연결된 동안 에이전트가 잡은 예약도 들어가고, Reset all을 누르면 이전 일정을 지우고 새 일정으로 바꾼다. 달력 주 제목 옆에 복사한 날짜(누르면 Google Calendar가 열림), 동기화 중, 실패가 보인다. Google 오류는 "sync failed"로만 보이고 예약과 답장에는 영향을 주지 않는다.
  - Disconnect를 누르면 그 캘린더와 일정을 지우고 권한을 취소한다. 결과는 popup으로 알린다.
  - OAuth state는 서명하고 Connect를 누른 브라우저의 cookie에 묶는다. refresh token은 암호화해 방문자 저장소에 둔다. 동의 화면용 개인정보 처리 안내는 `/privacy.html`이다.
  - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`이 없으면 Sync는 503으로 끝난다(`backend/AGENTS.md`).
- 처음 로그인한 테스터에게 온보딩 슬라이드를 보여 준다(`frontend/src/Tour.tsx`, `frontend/src/lib/tour.ts`, 테스트 3개).
  - 화면 가운데 창에 9장: 데모 소개, 헤더(Today, Reset all, 화면 전환), 손님 카드, 손님 폰과 추천 답장, 예약 상태, Dave 달력과 Google Sync, 동네 요일과 요금표, Dave 폰, judgment log. 장마다 시뮬레이터 화면을 단순하게 그린 그림에 해당 영역을 강조한다.
  - Back / Next나 ← / →로 넘기고, 오른쪽 위 Skip이나 Esc로 닫는다. 열려 있는 동안 뒤 화면은 누를 수 없다.
  - 닉네임별로 이 브라우저에서 처음 한 번만 저절로 열리고, Google 연결에서 돌아온 직후에는 열리지 않는다. 헤더 제목 옆 How it works로 언제든 다시 본다.
- `backend/README.md`, `frontend/README.md`에 로컬 실행 방법을 적었다: 설치, `.dev.vars`와 로컬 allowlist 준비, dev server(backend 8787을 먼저, 그다음 frontend 5180), 로그인과 token을 쓰는 curl, 브라우저에서 시뮬레이터 쓰는 법.

**아직 안 되는 것**
- 답장 품질: 가끔 목록 형식으로 답하거나, 인사에 주소와 마당 크기를 묻는다. 공개 전 E2E 테스트로 다듬는다.
